# Планирование астрономических наблюдений

REST-сервис для клуба любителей астрономии: каталог небесных объектов и телескопов, планирование сеансов наблюдения и журнал наблюдений. Данные хранятся в PostgreSQL.

Стек: Java 21, Spring Boot 4.1.1, Spring Data JPA, PostgreSQL, Maven.

## Сущности

| Сущность | Адрес | Что хранит |
|---|---|---|
| Пользователь | `/api/users` | наблюдатель: имя, email |
| Небесный объект | `/api/celestial-objects` | название, тип, минимальная апертура телескопа (мм) |
| Телескоп | `/api/telescopes` | название, апертура (мм), свободен ли, на обслуживании ли |
| Сеанс наблюдения | `/api/observation-sessions` | кто, каким телескопом, какой объект, когда, статус |
| Наблюдательная запись | `/api/observation-records` | сеанс, время (ставит сервер), описание, оценка качества 1–5 |

Связи: сеанс ссылается на пользователя, объект и телескоп; запись ссылается на сеанс. При удалении пользователя, объекта или телескопа удаляются их сеансы, при удалении сеанса — его записи.

Статусы сеанса: `PLANNED` (запланирован) → `IN_PROGRESS` (идёт) → `COMPLETED` (завершён), либо `CANCELLED` (отменён).

Для каждой сущности есть CRUD: `GET /api/...`, `GET /api/.../{id}`, `POST /api/...`, `PATCH /api/.../{id}`, `DELETE /api/.../{id}`.

## Бизнес-операции

| Операция | Запрос | Правила |
|---|---|---|
| Начать сеанс | `POST /api/observation-sessions/{id}/start` | только запланированный сеанс; телескоп свободен и не на обслуживании; телескоп становится занятым |
| Завершить сеанс | `POST /api/observation-sessions/{id}/complete` | только идущий сеанс; нужна хотя бы одна запись; телескоп освобождается |
| Отменить сеанс | `POST /api/observation-sessions/{id}/cancel` | только запланированный сеанс |
| Перенести сеанс | `POST /api/observation-sessions/{id}/reschedule` | только запланированный; не в прошлое; телескоп не занят другим сеансом в это время |
| Отправить телескоп на обслуживание | `POST /api/telescopes/{id}/maintenance` | нельзя, если на телескопе идёт сеанс; запланированные сеансы на нём отменяются |
| Вернуть телескоп с обслуживания | `POST /api/telescopes/{id}/return` | только телескоп на обслуживании |

Дополнительные правила: сеанс нельзя создать для объекта, которому не хватает апертуры телескопа; записи добавляются только в идущий сеанс; нельзя удалить пользователя, объект, телескоп или сеанс, пока сеанс идёт.

Ответы: `200` — успех, `201` — создано, `204` — удалено, `400` — неверные данные, `404` — не найдено, `409` — операция недопустима в текущем состоянии.

## Запуск

1. Установить PostgreSQL и создать пользователей и базу (под суперпользователем):
   ```sql
   CREATE ROLE rbpo_owner LOGIN PASSWORD 'пароль_владельца';
   CREATE ROLE rbpo_service LOGIN PASSWORD 'пароль_сервиса';
   CREATE DATABASE rbpo_2026 OWNER rbpo_owner;
   REVOKE ALL ON DATABASE rbpo_2026 FROM PUBLIC;
   GRANT CONNECT ON DATABASE rbpo_2026 TO rbpo_service;
   ```
   `rbpo_owner` владеет схемой и создаёт таблицы. `rbpo_service` — пользователь приложения: только чтение и изменение данных (`SELECT, INSERT, UPDATE, DELETE`), без права менять структуру таблиц.
2. Скопировать `.env.example` в `.env` и вписать пароли. Файл `.env` не попадает в git.
3. Первый запуск (создать таблицы и тестовые данные, повторный запуск сбрасывает данные):
   ```bash
   ./mvnw spring-boot:run -Dspring-boot.run.profiles=db-init
   ```
4. Обычный запуск:
   ```bash
   ./mvnw spring-boot:run
   ```

Структура БД — `src/main/resources/schema.sql`, тестовые данные — `src/main/resources/data.sql`.

## Коллекция запросов

`postman/zadanie-3.postman_collection.json` — импортировать в Postman. Папка «Сценарий» проходит путь от создания данных до всех бизнес-операций; папки по сущностям содержат CRUD. Перед прогоном сценария перезапустить приложение с профилем `db-init`.
